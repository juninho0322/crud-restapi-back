    Study plan

    Use this order when learning the project from frontend to backend.

    1

    Click the app

    Create, edit, complete, and delete a task. Watch the request panels change.

    2

    Start at frontend

    Read public/app.js. Find apiRequest(), saveTask(), and loadTasks().

    3

    Enter Express

    Read src/app.js. This file connects middleware, frontend files, and API routes.

    4

    Follow routes

    Read src/routes/taskRoutes.js. Match each HTTP method to a controller.

    5

    Read controllers

    Read src/controllers/taskController.js. Look for req, res, validation, and repository calls.

    6

    Finish at storage

    Read src/repositories/taskRepository.js. This is where local JSON or Supabase is used.

    Who talks to who

    The dependency direction should always move downward.

    public/app.js
  -> fetch("/api/tasks")
  -> src/app.js
  -> src/routes/taskRoutes.js
  -> src/controllers/taskController.js
  -> src/validators/taskValidator.js
  -> src/repositories/taskRepository.js
  -> local data/tasks.json or Supabase Postgres

    Project structure

    Read from top to bottom to see what depends on what.

    public/app.js
  -> calls /api/tasks with fetch()

src/app.js
  -> receives /api/tasks
  -> sends it to src/routes/taskRoutes.js

src/routes/taskRoutes.js
  -> chooses the controller function

src/controllers/taskController.js
  -> reads req
  -> calls validator/repository
  -> sends res

src/repositories/taskRepository.js
  -> reads and writes data/tasks.json

    Frontend vocabulary

    Small words that appear everywhere in browser code.

    DOM
    The page tree that JavaScript can read and change.
    Event listener
    A function that runs after a click, submit, or other browser event.
    fetch()
    The browser function used to call the REST API.
    State
    Values the frontend keeps in memory, like the task list and active filter.
    Render
    Turning JavaScript data into visible HTML on the page.
